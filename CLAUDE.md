## Learnings

At the end of every session, append one line here: what broke, or what you'd do differently.
- B2 (2026-08-18): Aaron's `lib/redact.ts` was already merged (Luhn-validated); fake card numbers in fixtures must pass the Luhn check or they won't be redacted — use standard test numbers (4111 1111 1111 1111) not invented ones. Also: `npm run` scripts on Windows can't use `node_modules/.bin/tsx` directly — just `tsx` works because npm adds `.bin` to PATH automatically.
- B1/C1/D2 (2026-08-18): PowerShell here-strings (`@'...'@`) can't contain single-quoted apostrophes — git commit messages with contractions ("don't") break the heredoc. Use a temp file for complex PR bodies and `git commit -m "..."` with escaped content for messages. Also: `sessions.pending_documents` JSONB repurposed for Q&A conversation history works but is semantically wrong — future migrations should add a dedicated column rather than repurposing document-queue fields.
- A1 (2026-08-18): the shared dev cluster had zero tables before this session — B1/B2/C1 all developed against mock-db.json fixtures and never actually ran their migrations for real, despite 001-003 already existing in db/migrations/. Don't assume a migration file existing means it's been applied anywhere. Also: this sandboxed session had no Node.js at all (not just missing tsx-on-PATH) and no working cockroach/DB MCP tool despite the issue text claiming one — had to verify the schema by reading `.env`'s COCKROACH_DATABASE_URL directly and hitting the cluster with Python/psycopg2 in a throwaway `.venv` (already gitignored) as a stand-in for the real `pg`-based TS runner. `.env` in this repo uses `KEY = "value"` (spaces + quotes) not plain dotenv `KEY=value` — a naive regex/parser will silently miss it.
- A2 (2026-08-18): an earlier attempt at A2 (`origin/track/a/a2-ingestion-rebase-fix`, never opened as a PR) implemented the whole pipeline in Python via AWS SAM (`services/ingestion-A2/`), with its own `redaction.py` and its own direct `audit_log` INSERT — duplicating `lib/redact.ts` and bypassing `lib/audit.ts` in a second language. Rewrote it as `services/ingestion/s3-extraction/` in TypeScript instead, importing both shared helpers directly. Also: added `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner` to `package.json` but could not run `npm install` (no Node in this sandbox, same as A1/D1) — `package-lock.json` is now out of sync with `package.json`; whoever picks this branch up must run `npm install` before `npm ci` will work in CI.
- D1 (2026-08-18): before writing server-side RBAC, check `services/web/src/lib/rbac.ts` — Bryan's front end already has a real capability matrix and its header says outright the UI copy is decorative and "the real enforcement lives in services/api / D1." Mirror that matrix exactly rather than inventing a different permission model from the issue's prose spec; the two disagreed slightly (issue text implied data_entry has no transaction visibility, the UI matrix grants `view_row_level_transactions` to data_entry) and the deployed UI won. Also: this sandboxed session again had zero Node.js (same as A1's note) — couldn't run `vitest`/`tsc` locally at all, had to review the TS by eye and rely on CI/the user to actually execute `npm test`.
- CI-widening session (2026-08-18): Node.js *was* installed this time (`C:\Program Files\nodejs`, machine PATH updated) but the sandbox's shell processes were spawned before the install and cached the old PATH — `node`/`npm` still reported "not found" until commands explicitly prepended `/c/Program Files/nodejs` (bash) each time. If Node ever "should be there but isn't," check for a stale-PATH shell before assuming it's actually missing. Also: root `tsconfig.json` only ever covered `lib/**` and `db/**` — `services/agent`, `services/ingestion/embeddings`, and `services/api/summaries` had literally never been typechecked. Widening it immediately surfaced a real bug in all four Bedrock `client.ts` files (agent, summaries, embeddings, template-gen): `resp.output?.message?.content?.[0].type !== 'text'` doesn't compile because the AWS SDK's `ContentBlock` union has no `type` discriminant field — fixed to `!('text' in block)`. Separately, `scripts/lint.mjs` recurses into `services/**` with no `node_modules` exclusion — harmless when nothing was ever `npm install`ed there, but once `services/web`/`template-gen` have real `node_modules` it silently scans thousands of vendored files and blows past a 60s timeout. `services/agent`, `services/ingestion/embeddings`, and `services/api/summaries` had zero test coverage despite being merged, demo-critical modules — added `test/agent.test.ts`, `test/search.test.ts`, `test/template-gen.test.ts` (mirroring the existing `vi.mock('.../client')` pattern from `test/summaries.test.ts` rather than hitting real fixture files, since those modules write mock state to a checked-in `mock-db.json` and a test suite shouldn't leave the working tree dirty).
- D26 merge-with-main session (2026-08-18): `git merge origin/main` into `track/d/26-api-server` was a clean auto-merge, zero conflicts (main hadn't touched `tsconfig.json`/`lint.mjs`/`ci.yml`, and both sides' independent `CLAUDE.md` Learnings appends merged line-wise fine). Also: EnterWorktree on a cwd-pinned subagent, given the path of an *already-checked-out* worktree belonging to a different session, reports success but then Bash/PowerShell refuse every command in that dir ("must run inside its worktree") — the actual fix was creating a differently-named local branch (`git checkout -b d26-work origin/track/d/26-api-server`) inside the agent's own pinned worktree and pushing it to the remote branch ref explicitly (`git push origin d26-work:track/d/26-api-server`) rather than trying to check out the same-named branch locally. On A2's new TS rewrite (`services/ingestion/s3-extraction/`, PR #28, no `package.json` of its own): checked `client.ts` for the same `ContentBlock`-union bug fixed elsewhere this week and it was a false alarm — `resp.output?.message?.content?.[0]` accesses `.text` directly with no `'text' in block` guard, which looks identical to the buggy pattern, but the installed AWS SDK's `ContentBlock.*Member` interfaces already declare `text?: never` on every non-text member (not just omit it), so `.text` type-checks as `string | undefined` on the whole union without narrowing — `tsc --noEmit` was clean before touching anything. Left it alone per "don't speculatively fix working code." Wired the module into root `tsconfig.json`'s `include` (no dedicated CI job needed, unlike `template-gen`, since it has no separate `package.json`/deps) and added `test/s3-extraction-repository.test.ts` + `test/s3-extraction-upload.test.ts` (mocking `client.ts`'s `readMockDb`/`writeMockDb`/`IS_MOCK` and `repository.ts`'s `recordUpload` respectively) alongside the pre-existing `test/s3-extraction.test.ts` (which main already shipped, covering `key.ts`/`extract.ts` only) — `repository.ts` and `upload.ts` had zero coverage before this.
