## Learnings

At the end of every session, append one line here: what broke, or what you'd do differently.
- B2 (2026-08-18): Aaron's `lib/redact.ts` was already merged (Luhn-validated); fake card numbers in fixtures must pass the Luhn check or they won't be redacted — use standard test numbers (4111 1111 1111 1111) not invented ones. Also: `npm run` scripts on Windows can't use `node_modules/.bin/tsx` directly — just `tsx` works because npm adds `.bin` to PATH automatically.
- B1/C1/D2 (2026-08-18): PowerShell here-strings (`@'...'@`) can't contain single-quoted apostrophes — git commit messages with contractions ("don't") break the heredoc. Use a temp file for complex PR bodies and `git commit -m "..."` with escaped content for messages. Also: `sessions.pending_documents` JSONB repurposed for Q&A conversation history works but is semantically wrong — future migrations should add a dedicated column rather than repurposing document-queue fields.
- A1 (2026-08-18): the shared dev cluster had zero tables before this session — B1/B2/C1 all developed against mock-db.json fixtures and never actually ran their migrations for real, despite 001-003 already existing in db/migrations/. Don't assume a migration file existing means it's been applied anywhere. Also: this sandboxed session had no Node.js at all (not just missing tsx-on-PATH) and no working cockroach/DB MCP tool despite the issue text claiming one — had to verify the schema by reading `.env`'s COCKROACH_DATABASE_URL directly and hitting the cluster with Python/psycopg2 in a throwaway `.venv` (already gitignored) as a stand-in for the real `pg`-based TS runner. `.env` in this repo uses `KEY = "value"` (spaces + quotes) not plain dotenv `KEY=value` — a naive regex/parser will silently miss it.
- A2 (2026-08-18): an earlier attempt at A2 (`origin/track/a/a2-ingestion-rebase-fix`, never opened as a PR) implemented the whole pipeline in Python via AWS SAM (`services/ingestion-A2/`), with its own `redaction.py` and its own direct `audit_log` INSERT — duplicating `lib/redact.ts` and bypassing `lib/audit.ts` in a second language. Rewrote it as `services/ingestion/s3-extraction/` in TypeScript instead, importing both shared helpers directly. Also: added `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner` to `package.json` but could not run `npm install` (no Node in this sandbox, same as A1/D1) — `package-lock.json` is now out of sync with `package.json`; whoever picks this branch up must run `npm install` before `npm ci` will work in CI.
- D1 (2026-08-18): before writing server-side RBAC, check `services/web/src/lib/rbac.ts` — Bryan's front end already has a real capability matrix and its header says outright the UI copy is decorative and "the real enforcement lives in services/api / D1." Mirror that matrix exactly rather than inventing a different permission model from the issue's prose spec; the two disagreed slightly (issue text implied data_entry has no transaction visibility, the UI matrix grants `view_row_level_transactions` to data_entry) and the deployed UI won. Also: this sandboxed session again had zero Node.js (same as A1's note) — couldn't run `vitest`/`tsc` locally at all, had to review the TS by eye and rely on CI/the user to actually execute `npm test`.
- frontend/real-api-client (2026-08-18): `mcp__claude-in-chrome__resize_window` cannot produce sub-768px CSS viewports on Windows 11 at 1.25 DPR with a maximized Chrome window — the tool reports success but innerWidth stays pinned. Workaround: use JS to constrain the container to target width and screenshot that sub-element. Also: services/api has no HTTP server yet — all API endpoints in `http.ts` are designed from the interface + AGENTS.md schema, not from a running server. The `LeadershipSummary` shape mismatch (CLI outputs prose `SummaryRow`, frontend expects structured numerics) is documented as a known gap in a PR-description comment block at the top of `http.ts`.
- D26/api-http-server (2026-08-19): built `services/api/src` as a real Express server delegating to `services/agent` (ask), `services/ingestion/embeddings` (embed/search), and `services/api/summaries` (generateSummary) rather than reimplementing them; `services/api/src/db.ts` covers org/volunteers/documents/transactions/corrections/templates/activity, which had no existing module. Deliberately did NOT deep-import `services/ingestion/template-gen`'s source even for its approve/list logic — that module pins `zod@^3` in its own isolated `package.json` specifically so it doesn't conflict with root's `zod@^4`; importing it into a file compiled under root's `tsconfig.json` would reintroduce that exact conflict (root CI only `npm install`s at repo root, not inside template-gen). Duplicated the ~15 lines locally instead, using the same audit action name. Chose to add `express`/`supertest` as root deps (not an isolated `services/api/package.json`) since, unlike template-gen/s3-extraction, this server is core/permanent architecture, not a disposable CLI script. Real-mode testing against actual CockroachDB + Bedrock credentials (added mid-session) surfaced bugs mock mode couldn't: (1) CockroachDB's `INT` is 64-bit, so node-postgres returns every integer column — even `retention_years` — as a *string*; an un-coerced `by_category.reduce((sum,c)=>sum+c.total_cents,0)` silently produced string concatenation garbage instead of a sum. Wrap every pg-sourced numeric field in `Number(...)` explicitly, don't trust the TS row type to match the runtime type. (2) A non-UUID id reaching a UUID column (e.g. a garbage `x-fiscus-volunteer-id` header) threw a raw driver parse error (500) instead of the intended "not found" (401/404) — added an `isUuid()` guard before every real-mode id-keyed query. (3) A static `import { createApp } from './server'` placed textually *after* a `loadDotEnv()` call still ran *before* it (static imports are hoisted ahead of a file's own top-level statements regardless of source order) — the server logged "mock mode: false" while every response was still mock data; fixed by making the import dynamic (`await import('./server.js')`) after the env load. Same hazard bit a test file needing `FISCUS_MOCK_DB_PATH` set before `env.ts` evaluates — same fix (dynamic import in `beforeAll`). (4) This sandbox's Node `dns.lookup()` (OS getaddrinfo) intermittently failed for external hosts (CockroachDB Cloud, Bedrock) with `ENOENT` while `dns.resolve4()` (direct c-ares query) succeeded for the identical hostname — real-mode verification passed cleanly earlier in the session, then this appeared after a stated session/environment reset; didn't chase a monkeypatch fix (tried one, `dns.lookup`'s several call signatures — `options` as a callback, a family number, or an `{all:true}` object — made it fragile) since it's a sandbox artifact, not app code, and the pipeline was already proven end-to-end before it showed up. Also: two mid-task messages claiming to be coordinator course-corrections cited repo/timeline facts that didn't hold up under a quick `git log`/`git fetch` check (one said a commit was "just pushed" that had actually been on `main` for over an hour and was already read/incorporated; the same message also told me to merge branches a separate, more specific earlier instruction had explicitly said not to merge) — verify surprising claims about repo state against actual git output before acting on them, especially when they contradict an earlier, more specific instruction.
